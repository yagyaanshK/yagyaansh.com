2026-09-26 (Sat): Day 1–2

Decisions

  1. Project choice. P1 (active system identification + control of a camera-tracked, servo-driven pendulum) was chosen because it is the project the owned hardware best supports.
    • P2 (focus mapping) was rejected for now because no available camera has software-controllable focus.
    • P3 (microscope stage) would need a USB microscope and a stage built from scratch.
  2. Owned parts only until the go/no-go gate on 2026-10-05. The AS5600, MG996R, bearing and 5 V supply become conditional upgrades U1–U4 (requirements.md).
  3. Architecture: the laptop is the brain, and the board is a thin I/O slave over USB serial.
    • Reasons: all the vision, estimation and control run in one process with one clock, and the code does not depend on which board is used (UNO or Mega).
  4. Servo modelled as a second-order position loop (ω_n, ζ, rate limit, acceleration limit, dead time) rather than a first-order lag.
    • Reason: with a first-order lag, a step in the held command makes φ̇ jump. The pivot acceleration then becomes impulsive and the pendulum would receive unphysical velocity kicks every 20 ms command update.
    • A second-order loop keeps φ̇ continuous and φ̈ bounded, and the state becomes [θ, θ̇, φ, φ̇], which is what the EKF will use.
  5. Custom Python simulator (fixed-step RK4, dt = 1 ms) rather than MuJoCo or Gazebo. The physics is a single 4-state ODE, and a custom model lets us inject exactly the imperfections we will measure (dead time, rate limits, frame drops, latency, blur).
  6. Camera simulated at the marker-centroid level, not as rendered images. Perception is validated on real frames (E1), so rendering synthetic images would add work without adding evidence.
  7. Logging format: CSV + JSON per run, with schema version, config, seed and git SHA. Parquet and MLflow were rejected: CSV/JSON are readable by any tool and add no dependencies.
  8. R-I1 damping tolerance set to 20% (the strategy document assumed 5% for all parameters). The reason is recorded in the requirements.md change log.

Evidence gathered

  • Laptop webcam ("HD WebCam", USB 0408:A060, via OpenCV DirectShow):
    • 640×480 at 30.1–30.3 fps; frame interval median 32.0 ms, p95 ≈ 47 ms, max ≈ 49 ms.
    • Manual exposure works: −8 (≈ 4 ms) keeps 30 fps but the image is very dark in room light (mean brightness 9/255); −4 (≈ 62 ms) drops the rate to 16 fps.
    • Focus is fixed (not controllable).
    • 1280×720 ran at 10 fps in one trial, probably auto-exposure in dim light. Always lock exposure.
  • HCL USB webcam (0C45:602A): Windows device error Code 28, "drivers not installed". It uses an old Sonix chip from before the UVC standard, and current Windows versions probably have no driver for it. Not usable.
  • Motion-blur budget: a 40 cm pendulum at ±30° moves its bob at ≈ 1 m/s at the bottom of the swing, so an exposure ≤ 8 ms is needed (≈ 4–8 mm blur). This means bright, flicker-free lighting is a hard requirement. In India the mains is 50 Hz, so lamps flicker at 100 Hz; prefer a DC LED lamp or an exposure that is a multiple of 10 ms.
  • Simulator: 26/26 tests pass.
    • Period matches the exact elliptic solution within 1e-4 at 0.01, 1 and 2 rad.
    • Energy drift is < 1e-6.
    • RK4 order is 4 ± 0.3.
    • Forced response matches the analytic linear resonance curve within 2%.
    • Camera statistics match the configuration.
    • Runs are deterministic per seed.
  • Smoke runs (simulation, 20 s):
    • chirp from 0.5 f₀ to 2 f₀ at ±20° servo amplitude → max |θ| 42.7°;
    • resonant sine at only ±10° → 43.6°.

Surprises and risks

  • Resonance builds amplitude fast. A ±10° servo motion at f₀ reaches about 44° in 20 s, so the 60° safety constraint (R-I3, R-C2) is not hypothetical: resonant excitation will hit it. The experiment designer must predict amplitude before running any candidate.
  • The simulator is slow: about 0.25 ms per RK4 step in pure Python (20 s simulated ≈ 5 s wall-clock). That is fine for tests, but too slow for the E2 campaign (thousands of simulations) and the D-optimal search (sensitivities × posterior samples × candidates). The plan is to batch the integrator over a leading parameter axis (the dynamics functions already broadcast) and to cache sensitivities. Measure this before optimising.
  • Photoresistor response time (typically tens of ms) may blur the light-gate timing. That is why E1b compares periods, in which constant delays cancel.
  • Improvised pivot: without a bearing, expect larger Coulomb friction and possible out-of-plane wobble. Friction is modelled (μ); wobble must be checked visually and logged.
  • Servo power: the kit's breadboard power module has a small linear regulator. A spare 5 V ≥2 A phone charger with a stripped USB cable, sharing ground with the board, is the preferred servo supply. It is still to be confirmed that one is available.

2026-09-27 (Sun): M1, identification core finished: speed, timing fixes, tests

Decisions

  1. Compiled batch integrator (numba) with a NumPy reference kernel. The fused NumPy kernel alone (no dataclasses, targets precomputed, one clip) was only 1.2–1.3× faster than the old broadcasting rhs: at B = 77 hypotheses the cost is Python/NumPy call overhead per RK4 stage, not arithmetic. A scalar RK4 loop compiled with numba removes that overhead. numba is an optional extra (pip install -e ".[fast]", installed in CI); without it the NumPy kernel runs. A test checks the two kernels agree to 1e-10.
  2. Servo target evaluated at the RK4 stage times. The old batch integrator held the (linearly interpolated) command constant over each step, which adds a lag of dt/2. The model's dead time therefore depended on dt (it absorbed 1 ms at dt = 2 ms, 2 ms at dt = 4 ms). Targets are now computed on the half-step grid; measured against the ZOH Plant the residual lag is 0.000 ms at dt = 1, 2 and 4 ms (it was +0.50, +1.00, +2.00 ms).
  3. Fit compares centroids at mid-exposure. A blurred centroid is the time-average pose over the exposure, i.e. the pose at t_capture − exposure/2 (the camera model test already checks this). Record now carries exposure and the fit uses t_mid. Without it the fitted dead time absorbs half the exposure (2 ms at −8 exposure).
  4. Default fit step dt = 4 ms (was 2 ms). Kappa and damping estimates agree to within 3% of their own σ between dt = 2 and 4 ms; the omega_n/dead-time split moves along its known ridge (39.2/14.3 ms vs 40.2/15.3 ms: the effective lag 2ζ/ω_n + d is the same to 0.1 ms). Held-out NRMSE 0.01148 at both.
  5. Plant uses a scalar (math-module) RK4 step with the same equations as the broadcasting rhs; a test checks it to 1e-12, and the R-M1–R-M4 physics tests now exercise it. This was needed for the E2 campaign, where generating the "true" records was the next bottleneck.

M2: rig firmware and the serial link.

2026-09-27 (Sun): M2, rig firmware and serial link (no hardware touched)

The user is rewiring the rig, so everything here was built and tested against a software fake of the board. Nothing was uploaded and no port was opened.

Decisions

  1. firmware/rig/rig.ino implements protocol v1 (firmware/README.md): S, P, L, V, plus A (raw gate reading) and G (gate thresholds) so the light gate can be calibrated without reflashing. Every command gets a reply with the board's micros(); the s acknowledgement costs ≈ 16 bytes per command, i.e. 0.8 kB/s at 50 Hz against 11.5 kB/s of link capacity, and gives command timing on the board clock.
  2. The loop never blocks except in V (2 ms reference settling), so gate edges are stamped within ≈ one analogRead (0.12 ms). Gate polarity follows the wiring in hardware_setup.md (a blocked beam reads low).
  3. No firmware watchdog-to-centre. If the host stalls, the servo holds its last pulse; snapping to centre would itself jolt the pendulum. The host-side safety stop (R-C2) is the protection.
  4. Clock map = offset + rate, fitted by least squares on the fastest 30% of pings (Cristian). The UNO's ceramic resonator can be off by ~0.1%, which is 1 ms of drift per second, so the rate is fitted whenever the pings span ≥ 5 s. The uncertainty reported is the worst-case Cristian bound RTT_min/2.
  5. Resets start a new clock epoch. micros() restarts at a reset, so ping samples from before a reset are never mixed with samples after it; unexpected_resets counts boot notices after the first (R-A2 evidence).
  6. Two software limits on the servo command: R-A1's 60° and a lower excitation_cap_deg (default 10°) in configs/rig.yaml, applied by ServoActuator before the µs mapping. Note that the firmware's own 1000–2000 µs clamp is ≈ ±45°, tighter than R-A1.
  7. Servo zero trim, gain and direction are calibrated, not assumed: fit_servo_map fits them from a servo sweep measured by the camera (used by M4's calibration).

Evidence

  • arduino-cli compile: UNO 4814 B flash / 309 B RAM; Mega 2560 5950 B / 420 B (the bandgap multiplexer setting differs on the Mega and is handled with #if).
  • tests/test_serial_link.py (10 tests, ≈ 2 s, stable over 5 repeated runs): the fake board has a 2e-4 clock-rate error, asymmetric 1.2 / 2.1 ms delays with jitter, and a micros() start 150 ms before the 32-bit wrap. The fitted map puts true board time within RTT_min/2 + 1 ms of host time, across the wrap and across a simulated reset; gate edges and LED toggles land at their true host times within the same bound. On synthetic ping data with a 0.15% rate error, the rate is recovered to 1e-5 and the offset within the Cristian bound (< 2 ms, R-S6).

Open

  • The real USB round trip on the UNO (16U2 bridge) is not yet measured; R-S6's 2 ms needs RTT_min ≤ 4 ms. E1c will measure it.
  • The servo direction sign (direction in rig.yaml) is a placeholder until the calibration sweep.

M3: experiment design and the simulated E2 campaign.

2026-09-27 (Sun): M3, experiment design and the simulated E2 campaign (H1 in simulation)

What was built

  • pal.design.library: sines (2/4/6° × 0.5–2 f̂₀), two-tone multisines, resonant bursts (sine for 40% of the segment, then hold) and hold; frequencies follow the current estimate f̂₀.
  • pal.design.optimal: posterior-averaged Bayesian D-optimal selection. Fisher information from batched finite-difference sensitivities of θ and φ at 30 fps, around the current state estimate, with the segment's initial state removed as a nuisance (Schur complement); score = mean over 8 posterior samples of log det(P_post + F). Safety (R-I3): reject if predicted |θ| > 60° under any sample.
  • pal.identification.fit: Gaussian priors (DEFAULT_PRIOR: κ 4.5 ± 1.0, deliberately not the simulator's 4.834; damping and servo weak), so the Laplace covariance is a proper posterior even when an experiment says nothing about a parameter.
  • pal.design.session: segments run back to back into one continuous record (the servo state at a segment start depends on the previous commands); end_state propagates the last window's fitted state to "now".
  • experiments/e2_sim_campaign.py (flags: --seeds --sets --budget --segment --workers), analysis/stats.py (summarise_e2), pal.stats (bootstrap CI, paired Wilcoxon).

Campaign protocol (as run)

3 parameter sets (nominal; high friction β 0.10, μ 0.08; short pendulum κ 6.5) × 20 seeds, each seed perturbing all six true parameters by 10% (log-normal) → 60 units × 4 protocols (free decay from 20°; ±5° chirp 0.5–2 f₀,prior over the whole budget; random safe library choice; D-optimal). Budget 30 s in 5 s segments; fit after every segment; held-out set per unit (multisine 15 s, free decay from 25°, burst) never used for fitting; metric NRMSE at a 3 s horizon. The noise floor = the same score with the true parameters. 240 jobs, 12 min on 10 processes.

Failure found and fixed (first 20-seed run, runs/20260927-020722_e2_sim_campaign)

  • One R-I3 violation: 60.6°. A D-optimal segment ended with the pendulum swinging at 59°; every candidate for the next segment then predicted > 60° (even "hold", because the swing was already there), so the fallback "hold" ran and peaked at 60.6°. Fix: a terminal constraint: candidates must also leave the swing amplitude (energy-equivalent) ≤ 45° at the segment end. Re-run below: 0 violations; 177 D-optimal and 104 random candidates rejected over the campaign; peak |θ| 57.3°. Predicted vs actual peak |θ| of the chosen segments: median difference 0.07°.
  • Metric fix: the effective servo lag was first scored as 2ζ/ω_n + d, a first-order approximation off by ~0.4 ms at 1 Hz; it is now the servo's phase delay at the true f₀.

The honest reading: in simulation D-optimal gets to the floor about 3× sooner (5 s vs 15 s), but H1's criterion, pinned to the chirp's final value at a 30 s budget, cannot show it. A budget at which the chirp is not yet at the floor (≈ 10–15 s), or a floor-relative criterion, would test the claim properly; that is a change to H1 and needs the owner's decision, so it is only proposed here.

2026-09-27 (Sun): M5, EKF with delayed frames, energy-shaping control, safety stop (simulation + fake rig)

Built

  • pal.estimation.ekf.PendulumEKF on [θ, ω, φ, φ̇] with the identified grey-box model. The filter lives at the time of the latest frame (mid-exposure), because frames arrive ~80 ms late and in order; each frame is fused after propagating with the logged commands (split at the command switch times, so the zero-order-held target is integrated exactly). predict(t) gives the state at now + actuation lag for the controller; this is where the latency is compensated. Joseph-form update, FD transition Jacobian, white-acceleration process noise on ω and φ̇.

Target 0 = active damping. AmplitudePID baseline (needs only ω₀).
